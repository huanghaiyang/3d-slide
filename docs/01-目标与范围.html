3d-slide
PHASE 01/ 目标与范围

SPATIAL PRESENTATION · PRODUCT BRIEF

把线性翻页，
变成一片可以飞翔的空间。

3d-slide 是一个浏览器端的空间演示工具。内容不再是逐页出现的卡片，而是共同存在于同一个三维场景； 讲述者用相机视点组织叙事，观众在场景之间连续移动，而不是翻页。

01 产品契约 WHO · WHEN · JOB · DONE
为 谁

需要把一件事讲清楚的人

汇报者、讲师、学生、设计师、创作者。不要求任何 3D 软件经验，也不需要设计团队协助。

何 时

关系比条目更重要时

需要展示层级、流程、对比、全景与局部的关系时，打开浏览器即可开始，无需安装或登录。

核心任务

在空间里摆内容，用视点讲故事

在空间画布上放置文本、图片与形状，捕获若干相机视点，形成一条可按顺序播放的空间路径。

完成证据

讲完一遍，且工作还在

在演示模式下从首视点走到末视点并退出；刷新页面后，作品与上次编辑视图仍在，并能导出为单个工程文件。

02 我们要解决的问题 OBSERVED PROBLEM
01

关系被切成页

层级、流程、对比被平均成同样大小的页面。观众记住了顺序，却记不住结构；讲完之后，脑子里没有一张完整的地图。

02

相机比画布更吓人

空间演示的门槛不在排版，而在取景与路径。非设计用户在三维视图里很容易迷路：不知道该往哪里飞，也不知道怎么回来。

03

素材与交付常常要妥协

图片、中文排版、离线演示，在既有工具里常被当作附加项。我们不打算让这些成为用户需要额外解决的问题。

PRODUCT RESPONSE

所有内容放在一个连续的空间里，叙事只由相机视点负责。 用户只需要会摆画面、会取景，不需要建模、不需要写动画时间轴。

摆内容 → 设视点 → 演示 → 带走
03 目标（可观察） OUTCOMES, NOT SLOGANS
G1

首次使用者完成闭环

不依赖教程，完成「新建 → 加内容 → 设视点 → 演示」四步，并知道下一步该做什么。

G2

观众感知到连续空间

视点切换表现为相机飞行，而非页面淡入淡出；观众能说出「从全景到了局部」。

G3

工作不会消失

刷新、关闭标签页、重新打开浏览器后，作品内容与上次编辑视图均可恢复。

G4

作品可以带走

导出一个 .slide 工程文件，在另一台装有本工具的浏览器中完整打开。

G5

用户不会在空间里迷路

任何时刻都能一键回到默认视图或聚焦选中对象；演示中可随时回到当前视点。

04 范围 P0 · P1 · NOT DOING

P0 · 最小完整闭环

IN SCOPE
  • 作品管理：新建、重命名、最近作品、删除二次确认
  • 空间编辑：三维视图、平移 / 环绕 / 缩放、重置视图、聚焦对象
  • 内容对象：文本、图片、矩形 / 椭圆 / 直线；位置、深度、缩放、旋转、透明度、可见性、图层顺序
  • 叙事路径：捕获视点、更新视点、重命名、拖拽排序、删除、过渡时长
  • 演示模式：全屏、前进 / 后退、自由浏览、回到路径、退出回编辑器
  • 持久化：本地自动保存、重新打开恢复、撤销 / 重做
  • 迁移：.slide 工程文件导出与导入

P0 明确不做

OUT OF SCOPE
  • 账号、云同步、只读分享链接（依赖服务端，P1 另行定义）
  • 模板库、自动播放、演讲者备注 / 双屏观众视图
  • 对象入场 / 退场动效、视频素材、3D 模型导入
  • 对象沿 X / Y 轴的 3D 倾斜、光照与材质编辑
  • PPTX / PDF 导入导出；空间布局无法在平面幻灯片中保真，不承诺降级转换
  • 移动端编辑；P0 只保证桌面浏览器上的编辑与演示
P1 · 候选 模板与预设路径 自包含 HTML 导出 分享链接 3D 倾斜与视频 演讲者备注 移动端演示 多选与批量编辑
05 关键产品决策 DECISIONS & TRADE-OFFS
ID决策为什么代价 / 边界
D1
本地优先，免登录
 打开就能用，不把账号当成使用前提；作品保存在浏览器本地。 跨设备需靠 .slide 文件携带；无实时协作。
D2
叙事是相机路径，不是对象动画
 内容始终存在于空间中，视点只移动相机。空间连续性成为产品承诺。 P0 不支持入场 / 退场与逐对象动画。
D3
视点捕获当前视图
 用户用摆姿势导演，不填写相机坐标；捕获比调参更接近直觉。 必须提供可靠的取景辅助：默认视图、聚焦对象、重置视图。
D4
演示可自由浏览，翻页回路径
 讲解时可临时放大细节；下一次翻页仍从当前位置飞向下一个视点。 观众可能暂时离开叙事线，需要用「回到当前视点」收束。
06 边界、假设与风险 ASSUMPTIONS

环境边界 ASSUMPTION

  • 01桌面浏览器最近两个大版本；视口建议 ≥ 1280×720
  • 02支持全屏 API；被拒绝时降级为全窗口演示
  • 03P0 固定 16:9 取景安全框，编辑与演示所见一致

容量假设 TBD

  • 01单作品 ≤ 200 个对象、≤ 50 个视点
  • 02单张图片 ≤ 20MB，工程文件 ≤ 200MB
  • 03自动保存 2 秒防抖；撤销至少 50 步

主要风险与缓解

  • 01迷路 → 默认视图、聚焦对象、演示「回到当前视点」
  • 02大图卡顿 → 容量上限 + 加载失败占位与重试
  • 03本地空间不足 → 保存失败提示 + 导出工程兜底
REVIEW FOCUS
  • 01P0 边界是否足够克制，又没有切断闭环？
  • 02「视点捕获当前视图」是否符合你的讲解直觉？
  • 03固定 16:9 是否可接受，还是必须支持竖屏？
